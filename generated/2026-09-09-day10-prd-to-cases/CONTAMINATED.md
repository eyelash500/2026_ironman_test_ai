# run-B-contaminated-01 ~ 05 為什麼作廢

跑完之後才發現，受測環境有兩個預先注入的來源，而提示詞刻意不給的東西，
它們都給了。

## 一、`qa-test-docs` skill 被觸發

作者自己安裝的 skill，description 明寫「即使使用者只提到其中一份文件
（例如「幫我寫 test case」），也應觸發此 skill 來確保格式一致」。

比對結果，輸出直接套用該 skill 的 `templates/test-case-template.md`：

| 輸出裡出現的 | 範本位置 |
|---|---|
| 「自動化標記說明」+ Auto／Semi／Manual 三級表 | 範本 11–19 行，逐字 |
| 「Case ID 命名規則」+ 前綴對照表 | 範本 23–33 行，連 `AC` 前綴都相同 |
| 表格含「優先級 P0/P1/P2」「自動化」欄 | 範本 41 行的七欄 |

提示詞刻意沒有提測試技法、沒有提優先級、沒有提自動化分級——
這些全部來自範本。所以 B 與 A 的產出量差距（中位 53 對 14），
無法歸因於模型能力。

## 二、對話框的 memory 預設開啟

受測環境可讀取先前對話，而作者與同一模型討論過本系列的四個缺陷、
十個歧義現場與跨路徑 (1+r) 推導。

這使得 B 產出中那些精準指向已知缺陷的「不得等於」斷言
（例如「不得等於期末年金結果 1,115,646.26」）出現兩種無法區分的解釋：

1. 從 PRD 條款的措辭反推出修正方向
2. 直接回憶起先前對話的內容

**作廢的理由不是它答錯，是無法說明它為什麼答對。**

## 保留原因

這五份不刪。它們是另一個對照的資料：同一個模型，
有團隊範本／有記憶 vs 完全隔離。那個比較本身有價值，
只是不能用來回答 Day 10 的問題。

# run-A-unisolated-01 ~ 05 為什麼也不能用

Gemini 端未掛 Gem、未掛檔案，但**「個人化智慧服務」為開啟狀態**。
那是 Gemini 的記憶功能，會讀取先前對話。

而受測物本身是 2025 年用 Gemini 協作做出來的，作者也曾請 Gemini
解釋過那段計算邏輯（見 2025 系列 Day 8）。因此該帳號的對話歷史
與受測物直接相關。

## 與 B 的差別：證據等級不同

| | A | B |
|---|---|---|
| 注入來源 | 個人化智慧服務（記憶） | qa-test-docs skill + memory |
| 產出中是否可見注入痕跡 | **看不到** | 看得到（範本結構、指向缺陷的斷言） |
| 標籤 | 隔離不完全（unisolated） | 已污染（contaminated） |

A 的五份輸出沒有任何回憶的跡象：沒有套用任何範本、沒有出現指向
已知缺陷的斷言，14 條案例幾乎是 PRD 條款的逐條轉寫。

**但「看起來乾淨」不是乾淨。** 隔離條件沒滿足就標記，
不能因為結果看起來沒問題就放行——那是用結果去判定方法的有效性，
正是本系列一路在避免的事。

## 保留原因

同 B：這十份是「隔離不完全」的對照組。重跑後若乾淨版的產出
與這批有明顯差異，那個差異本身就是「介面預設值會影響量測」的實證。
